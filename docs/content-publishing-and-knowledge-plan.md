# 内容发布与助手知识库方案

2026-10-02。本文保留最初设计方案。后续已实现构建时 Notion 同步、项目关联、文章目录、标签筛选、RSS 和文章章节引用；当前配置与实际行为以 README 为准。尚未配置只读集成令牌，未完成真实 Notion API 同步验证。

## 当前实现

- `/blog` 跳转到 `/notes`，文章来自 `lib/notes.ts`，详情页预生成且 `dynamicParams = false`。新增文章需要改文件并重新构建。
- `/bookshelf` 已改为阅读札记，暂不显示原书单，也没有发布虚构的摘抄。
- 助手知识来自 `lib/assistant/knowledge.ts`，项目片段复用 `lib/projects.ts`，另有手工维护的中文摘要、关键词与个人经历。
- `retrieve.ts` 对关键词和文本匹配打分，取最多四个片段；不是向量检索。
- `/api/portfolio-assistant` 先生成本地回答。只有模型和 Redis 配置都可用、预算允许时才调用模型；模型失败则回退。Redis 用于限流和回答缓存，不是文章知识库。

## 推荐：Notion 写作，网站展示

个人作品集优先使用 Notion 作为编辑后台。网站不需要再做管理员登录和富文本编辑器，也不要求新增数据库。网站自身的视觉与文章排版仍然可定制。

建立一个内容数据库，字段包括：标题、固定 slug、类型（博客/阅读札记）、状态（草稿/已发布/归档）、摘要、标签、发布日期、最后修改时间、是否允许助手引用。阅读札记补充原文标题、作者、来源 URL、章节或页码。正文中分开存放摘抄与个人感想。

推荐同步流程：

1. 在 Notion 新建页面、写正文、预览，设为已发布。
2. 服务端同步器通过只读集成读取指定数据库，只处理已发布条目。
3. 转换支持的 block 为网站可渲染结构，清洗外部链接并处理图片；不支持的 block 明确记录，不静默丢失。
4. 校验 slug 唯一、正文非空、来源字段有效；保留最近一次成功快照。
5. 网站更新列表、详情、站点地图及关联搜索；下架和删除也必须同步。
6. 允许助手引用的内容更新知识片段与版本，旧回答缓存随版本失效。

可以先在部署构建时同步到 JSON 快照：不需要数据库，内容更新需要重新部署。以后需要更及时发布，再做定时同步和服务器缓存。访问密钥只存服务端，勿交给浏览器；需接入授权的 Notion 数据库后才能实际同步。

详情页需改造当前静态 slug 限制，保证新文章在同步后可访问。预览仅自己可见，草稿不进入搜索、助手上下文或公开缓存。

## 如果选择本站后台

需要持久化存储、管理员认证、编辑器、草稿预览、发布/撤回、图片存储、修订历史及备份。PostgreSQL 足以承载博客和札记。两类内容共用 `posts`，用 `kind` 区分，札记额外保存 `source_title/source_author/source_url/source_location`。

每次写入都校验管理员权限，不能只隐藏按钮或检查后台页面。公开查询只返回已发布内容。发布成功后再刷新网站缓存，失败不能显示已发布。此方案可行，但对目前以作品展示为主的网站，维护成本高于 Notion。

## 助手知识库

内容少时保留现有检索，并补充中文别名与常见问法。先测代表性问题，避免资料有答案却检索不到。没有依据时明确告知，并提供相关页面链接。

知识增加后，采用检索增强生成（RAG）：

- 原文：来自 Notion 已发布文章、网站项目资料；Notion 是编辑来源，不能直接把整库传给模型。
- 分块：按标题和段落拆分，每块保留稳定 ID、正文、来源 URL、更新时间、版本和公开状态。
- 向量：由 embedding 模型生成，存 PostgreSQL 的 pgvector 列；原文与向量分开理解，向量不会替代正文。
- 查询：问题生成向量，结合关键词/项目别名召回，去重排序后取少量片段交给模型，输出可核对的引用。
- 权限：先过滤公开且允许引用的内容，再检索。私人笔记、简历隐私及草稿不进入公开知识库。
- 更新：对内容计算 hash，只重建变更片段。撤回文章时移除片段，并使旧回答缓存失效。
- 中文：不要默认 PostgreSQL 英文全文检索能处理中文分词；初期用中文别名和字符匹配，后续结合多语言 embedding 实测召回。

关系：Notion（写作）→ 同步快照（公开展示）→ 公开片段/向量（检索）→ 助手 API（回答）。网站页面和助手尽量来自同一份公开内容，避免两套事实各自更新。

## 优先继续优化的内容

1. 先打通写作与发布，再增加文章标签、搜索、目录和上一篇/下一篇。
2. 阅读札记明确区分原文摘抄与个人感想，保留来源，不先堆书单。
3. 项目详情补充做法、关键取舍、验证记录和最近更新；相关博客直接链接项目。
4. 助手优先做好中文召回、引用准确性、无依据回答和撤回内容同步，再考虑更复杂的多轮对话。
5. 有持续内容以后再加 RSS，方便订阅。
