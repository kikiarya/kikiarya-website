# Kikiarya 个人网站｜视觉、内容与交互升级方案

日期：2026-09-09  
阶段：设计提案，尚未实施。  
目标：更好看、更具技术感、更有个人特色，同时让访客快速理解作品和个人贡献。

## 1. 本次升级的方向

建议采用 **Sakura Systems Studio｜樱色系统实验室** 作为内部设计方向：保留 Kikiarya 的温柔色彩和少量编辑式衬线字体，引入清晰的技术排版、系统图形和可以亲手操作的小型实验。

访客应该同时感受到：这是一个有审美的人，也是一个真正理解系统、愿意解释技术的人。

本方案响应本次“更加科技化、有趣、有新颖交互”的要求，允许调整旧方案中的色彩、字体、装饰和页面结构。与 `folio-craft.md` 中“科技感只加在交互”“不要另开方案”等历史约束冲突时，本次提案采用这里的新方向。旧文档保留作为历史记录，不自动改写。

### 1.1 三个体验目标

1. **快速了解**：首页首屏看得到身份、研究方向和作品按钮；进入项目后，先看到问题、贡献、结果摘要。
2. **愿意探索**：至少有一个无需输入长文本、无需登录、十秒内能玩明白的交互。
3. **留下记忆**：形成一个与 Agent 有关的签名视觉物体，让素材、项目图和动效共享同一种语言。

### 1.2 现状依据与边界

本方案依据本次已查看的线上封面、首页、Work、Coding Agent 详情，以及本地首页、字体、动效和内容文件。线上与本地后续可能不同步，实施前需要重新确认。

- 桌面约 1280 × 720 视口下，首页主标题与长介绍把主要按钮推到首屏以下。
- 首页代表项目之前存在完整的 Trace 演示区域，作品出现偏晚。
- 项目列表以文字为主，代表项目的视觉差异不足。
- 小号导航和辅助文字偏淡；大标题、状态信息和技术标签层级需要重新平衡。
- 全局已有较多动效，新增交互应替换重复效果，并控制同时运动的区域。
- 本地 Notes 内容为空，Life 以求职状态为主，个人内容可以更具体。
- 本次未进行移动端实机检查、性能跑分或项目指标真实性核验；下文尺寸和预算是设计目标。

## 2. 视觉升级：颜色、材质和图形

### 2.1 推荐配色

以冷白纸面为主，粉色承担品牌识别，蓝紫色只用于技术交互的选中状态。正文保持深色，避免文字也全部变成半透明粉灰。

| 角色 | 初始建议值 | 用法 |
| --- | --- | --- |
| 页面底色 | `#F7F8FC` | 阅读区域，干净的冷白 |
| 实体卡片 | `#FFFFFF` | 项目、说明、结果 |
| 品牌浅色 | `#F6E8EF` | 封面局部、个人空间 |
| 正文主色 | `#232536` | 标题、正文、关键导航 |
| 正文次色 | `#555B70` | 摘要、辅助说明 |
| 品牌强调 | `#A83F71` | 主按钮、作品链接 |
| 交互强调 | `#5A52C8` | 当前节点、选中步骤、焦点 |
| 分隔线 | `#DDE0EA` | 网格、卡片边界 |
| 实验面板底色 | `#171B2B` | 小面积运行演示区域 |
| 深色面板正文 | `#EDF0FA` | 实验说明、节点文字 |

这些颜色需要在实际背景上检查对比度，不能仅凭色值认为已通过可访问性验收。普通文字以 4.5:1、大字以 3:1 为验收目标。

### 2.2 材质分配

- **首页与正文**：清晰的实体纸面，极轻的纹理；大段文字背后保持平静。
- **项目预览**：细边框、局部网格、节点和小型标注，形成技术图纸感。
- **实验区域**：允许一个深色面板，与浅色主站形成清晰层级；无需首版同时做完整明暗主题。
- **个人空间**：保留淡粉色、少量衬线和手写注释。
- 玻璃效果只用于导航或少数悬浮控件；避免每张卡片都有模糊、光晕和投影。

### 2.3 装饰替换表

| 当前元素 | 建议动作 | 新用途 |
| --- | --- | --- |
| 全站花瓣 | 降低频率，集中到封面和个人空间 | 保留品牌气质 |
| 蕾丝、蝴蝶结 | 从技术正文退出，少量保留在 Life | 区分内容区域 |
| 大范围粉色渐变 | 收缩到签名物体后方 | 引导视线 |
| 花瓣光标拖尾 | 默认使用原生指针，仅实验区有局部反馈 | 提升点击确定性 |
| 大圆角玻璃卡 | 按用途分为 12 / 20 / 28px 三档 | 建立组件层级 |
| 分隔装饰 | 使用编号、细线、节点、小型坐标标注 | 加强技术编辑感 |

## 3. 字体、字号和排版规范

### 3.1 字体分工

首版优先利用现有字体完成升级，再决定是否需要新字体。

- **Inter**：正文、导航、按钮、项目标题和多数技术页面标题。优先 400、500、600 字重；实际使用新字重时同步调整字体加载配置。
- **Cormorant Garamond**：品牌词标、封面短句、少量个人空间标题。减少它在技术长标题和小号状态文字中的使用。
- **JetBrains Mono**：代码、时间、数值、步骤编号。避免大段正文和所有导航都使用等宽大写字。
- **中文正文**：使用明确的中文无衬线回退链；中文格言可以保留宋体。长中文正文不要使用细衬线字体。
- **Great Vibes**：只有出现真实签名式内容时才保留，否则移除不使用的加载配置。

这样做的核心变化是：品牌仍然有诗意，技术内容更加清晰利落。

### 3.2 建议字号表

| 用途 | 宽屏桌面 | 普通笔记本 | 手机 | 行高 |
| --- | --- | --- | --- | --- |
| 品牌封面词标 | 88–104px | 72–88px | 48–60px | 1.0–1.1 |
| 首页主标题 | 72–80px | 56–64px | 36–44px | 1.08–1.15 |
| 项目详情标题 | 56–64px | 44–52px | 32–38px | 1.12–1.2 |
| 区块标题 | 36–44px | 32–36px | 26–30px | 1.2 |
| 项目卡标题 | 24–28px | 24px | 21–24px | 1.3 |
| 介绍文字 | 18–20px | 18px | 16–17px | 1.65 |
| 正文 | 16–18px | 16–18px | 16px | 1.7 |
| 导航与按钮 | 14px | 14px | 14–16px | 1.4 |
| 日期和标签 | 12–13px | 12–13px | 12–13px | 1.5 |

实施时使用流体字号，并同时检查窄桌面与手机。不要对所有标题直接套同一个 `text-hero`。

### 3.3 排版规则

- 桌面内容最大宽度建议 1200px；长正文限制在约 65–72 个拉丁字符宽度，中文另以实际阅读效果调整。
- 桌面 12 列、平板 8 列、手机 4 列；列间距分别从 24 / 20 / 16px 开始调试。
- 页面左右边距：手机 20px，平板 32px，桌面至少 40px。
- 区块间距：桌面 80–104px，手机 48–64px；不要每个区域都用超大上下留白。
- 卡片内边距：手机 20–24px，桌面 28–32px。
- 数值启用等宽数字，变化时不带动标签左右跳动。
- 导航字距控制在正常到轻微加宽；全大写编号可保留，普通词语不必全部大写。
- 标题、说明、按钮左边缘对齐；装饰不参与正文对齐计算。
- 技术详情页避免手工锁死标题换行，特别检查长单词和混合中英文。
- 在 1280 × 720 和 1440 × 900 下，首页介绍与主按钮应出现在首屏；手机允许标题自然换行，但入口不应被装饰挤走。

## 4. 页面具体改什么

### 4.1 封面

保留封面作为可探索的品牌场景，同时提供清晰入口。

- 增加身份说明：`AI systems · Research · Interactive experiments`。
- `ENTER` 改为 `Explore my work`。
- 个人空间使用文字入口 `Personal space`，花形符号作为辅助图标。
- 提供“直接看项目”入口，深链接访问作品时不经过封面。
- 首次访问可以展示，当前会话进入后不反复阻挡；Logo 返回首页，另设 `Open cover` 入口重看封面。
- 封面主视觉采用下文的“花瓣线路核”，取代额外叠加的多组散落装饰。
- 入口立即可用，文字动画不阻塞操作。

### 4.2 首页

推荐结构：

```text
导航：Kikiarya / Work / Lab / About / Contact
首屏：一句定位 + 两句介绍 + CTA | 签名交互物体
Selected work：三个代表项目，有图、有贡献摘要
Experience：实习与具体职责
Interactive lab：一个可操作的小实验
About / Now：兴趣、近况、毕业时间
Contact：明确可联系的事情和邮件入口
```

`Lab` 首版可直接指向首页实验区，`About` 指向介绍区；没有独立内容时不必增加空页面。Resume 保持显眼的按钮入口。

首屏文案草案，需要按实际项目状态确认：

> I build agents that can act, recover, and improve.
>
> Master’s student at the University of Sydney. My work explores agent post-training, runtime reliability, and interactive AI systems.

按钮：`View selected work`、`Resume`；GitHub 使用次级文字入口。

右侧状态卡压缩为三条：研究方向、毕业时间、当前状态。移除与正文重复的经历介绍。滚动时不让正文和按钮变透明。

### 4.3 Work 项目列表

- 三个代表项目使用有视觉素材的重点展示；其余项目使用紧凑列表。
- 卡片提供：项目名、一句问题描述、自己的贡献、一项可核验结果或交付物、详情入口。
- 展示标签从重复的 `Python / PyTorch` 改为更能区分项目的能力，如 `Policy training`、`Recovery`、`State compression`；完整技术栈放详情。
- 分类统一为内容类型，例如 Research / Agent Systems / Products / Other；避免同一层混合技术领域与课程属性。
- 小规模项目集保留轻量筛选即可；搜索放次级位置，筛选结果显示数量和空状态。
- 桌面重点项目可交替采用“图左文右”和“文左图右”；手机全部统一图上文下。

### 4.4 项目详情

推荐顺序：

1. 项目标题与问题摘要。
2. `My role / Period / Status`，明确个人职责、时间与当前阶段。
3. 两至三项关键贡献或结果，并给出依据入口。
4. 系统总览图。
5. 可交互的核心机制解释。
6. 关键技术决策、替代方案与取舍。
7. 评测设置、结果、边界和失败案例。
8. 相关项目或联系入口。

具体修正：

- Coding Agent 的 `ROLE` 当前放日期，拆分为职责和时间。
- 技术栈只保留一组，不在顶部重复展示。
- 关键实现以可完整阅读的列表呈现，自动切换剧场作为可选探索。
- 结果数字旁说明数据集、任务数量、基线、指标定义及证据来源。未完成的实验使用准确的阶段描述。
- LAR 的作者、论文链接、BibTeX 和投稿状态按正式来源核对后发布。
- 每页至少回答“我具体负责了哪部分”；团队结果与个人工作分别表述。
- 私有代码对应可公开的脱敏架构图或运行示例，不用一个无效 Repo 按钮占位。

### 4.5 Resume / Contact / Personal

- Resume 首屏给出下载入口、教育、方向、简短经历；下载按钮明确格式和语言。
- Contact 使用具体文案，例如欢迎交流 Agent systems、AI engineering 和研究合作；保留直接邮件入口与复制反馈。
- Notes 首先增加一到三篇真实短文，没有内容时不占主导航。
- Life 展示具体的照片、兴趣和故事，减少与简历重复的求职说明。
- Bookshelf 每本书增加一句个人感想；可选“正在读 / 已读 / 想读”筛选。
- 更新时间从统一内容字段读取，并只在真实更新时修改。

## 6. 新颖交互设计：让访客亲手理解你的项目

建议首版交付 **一个核心实验 + 一个品牌微交互**。其余作为后续内容，避免首页同时出现多套控制台。

### 6.1 核心实验：Agent Recovery Playground

**目标：** 让访客通过制造一次故障，理解 Agent 如何恢复。

**呈现：** 一张清晰的执行图，默认六个节点：Task → Plan → Edit → Test → Recover → Result。左侧图形，右侧显示当前步骤及简短说明。

**怎么玩：**

1. 点击 `Run demo`，执行路径逐步点亮。
2. 在测试阶段点击 `Inject failure`，选择测试失败或工具超时。
3. 切换 `Retry` 与 `Replan`，查看预设示例的不同路径。
4. 拖动时间轴回看，点击任意节点读取解释。
5. 点击 `Reset` 回到初始状态。

**反馈：** 当前节点有边框与文字标记，失败节点显示原因，恢复后标出回到的检查点。颜色之外必须有形状或文字区分。

**状态：** idle → running → failed → recovering → completed；运行中暂停与重置始终可用。重复点击不会启动多个播放循环。

**内容边界：** 初版使用本地确定性示例，界面明确写 `Interactive illustration`；不能把模拟过程描述为在线真实 Agent，也不展示假性能数字。

**手机端：** 转为纵向步骤列表和底部操作按钮，支持点击步进；不要求拖动、悬停或精确点击细线。

**验收：** 不读长说明也能发现运行按钮；用户可在十秒内主动触发一次状态变化；全过程可暂停、重放，并用键盘完成。

### 6.2 品牌微交互：花瓣线路核

**目标：** 把现有花瓣变成一个有技术含义的签名物体。

- 三片抽象花瓣代表 Policy / Tools / Memory，围绕中心任务节点布局。
- 悬停时相应路径高亮，出现一句解释；点击后进入对应项目。
- 指针移动只改变少量光照或最大约 3° 的局部倾角，不让链接位置追着鼠标移动。
- 默认静态或低频缓慢运动，离开视口后暂停。
- 手机显示三个可点击标签；减少动画模式使用静态 SVG。
- 提供明确的 `Explore a system` 文案，不能只靠用户猜测物体可点击。

首版使用 SVG 即可；只有在二维版本完成且效果确实不足时，再评估 3D。

### 6.3 项目实验：Token Compression Lens

**目标：** 解释 LAR 的压缩对象与保留边界。

- 左边展示带语义标记的原始示例，右边展示压缩后表示。
- 拖动滑块或点击预设档位，重复动作片段折叠，工具参数保持可读。
- 点击一个片段，在两侧同时高亮对应位置。
- 配置 `Show preserved arguments` 开关，强调哪些信息被保留。
- 默认不展示百分比；只有基于明确 tokenizer 计算的示例才展示 token 数量，并标注计算口径。
- 不把视觉缩短直接解释成真实准确率或吞吐量提升。
- 手机改为上下对照，提供按钮替代拖拽操作。

这是第二阶段适合做的内容型交互，放在 LAR 详情中，比继续增加首页装饰更有价值。

### 6.4 浏览交互：Project Constellation

**目标：** 展示不同项目之间的能力联系。

- Work 页面提供 `List / Map` 切换，列表为默认视图。
- 节点代表项目，连线代表共享能力，例如 evaluation、recovery、streaming。
- 点击某项能力时，仅突出相关项目；选中项目后出现摘要和详情链接。
- 节点位置采用固定布局，避免物理模拟导致文字不停移动。
- 映射依据来自真实项目内容，不把装饰连线伪装成数据分析结果。
- 手机使用按能力分组的列表，保留同等信息。

### 6.5 个人彩蛋：桌面小访客

如果你希望加入桌宠，可以作为用户主动开启的彩蛋：

- 入口放在 About / Personal，点击后小角色出现在页面角落。
- 支持点击问候、切换一两种动作，并引导去书架或个人空间。
- 可以关闭，记住本会话关闭状态。
- 不遮挡正文、按钮和手机底部导航，不自动播放声音。
- 角色素材需要单独确认使用权和风格一致性。

优先级 P2，先完成作品内容和核心实验。

## 7. 动效统一规则

| 动作 | 建议时长 | 规则 |
| --- | --- | --- |
| 按钮、标签反馈 | 150–200ms | 色彩、边框和轻微位移 |
| 卡片进入 | 300–450ms | 一次性，位移约 8–16px |
| 页面切换 | 250–400ms | 保持导航响应，不堆叠两次遮罩 |
| 实验步骤切换 | 300–600ms | 时长服务于理解，可暂停 |
| 封面进入 | 500–700ms | 允许跳过，链接始终可用 |
| 背景氛围 | 很低频或静态 | 离开视口暂停 |

- 同一视口尽量只保留一个主要动态焦点。
- 正文不随滚动消失，关键结果不需要等待计数动画才能看见。
- 重要信息不能只在 hover 中出现；触屏、键盘与鼠标能访问相同内容。
- 优先使用透明度和变换动画，避免大范围持续模糊。
- 遵循 `prefers-reduced-motion`；同时核查 JS 动画，不能只依赖 CSS 全局覆盖。
- 页面不可见时暂停循环；切换路由后清理定时器与事件监听。
- 保留原生滚动手感；平滑滚动组件只有在实际体验有收益时继续使用。

## 8. 内容整理清单

| 内容 | 要补什么 | 完成标准 |
| --- | --- | --- |
| 首屏介绍 | 一句定位、两句背景 | 不重复罗列关键词 |
| 三个代表项目 | 问题、职责、贡献、交付物 | 每项有具体名词和动作 |
| 项目结果 | 评测口径、来源、当前阶段 | 数字可追溯 |
| 实习经历 | 个人负责环节和解决的问题 | 区分团队成果与个人工作 |
| 系统图 | 图例、节点解释、阅读方向 | 无需观看动画也能理解 |
| Notes | 一至三篇真实短文 | 内容与个人经验有关 |
| Life | 真实兴趣与故事 | 不重复简历 |
| 联系页 | 欢迎交流的主题与邮箱 | 复制有反馈，邮件链接有效 |

可优先写的短文题目：

- 为什么 Agent 需要恢复机制，而不只是重试。
- 一个失败运行如何改变了我的系统设计。
- 我如何区分演示效果和工程证据。

这些是写作选题，需要以自己的真实经历填充。

## 10. 性能与验收

以下为目标预算，不代表现站测量结果：

- 项目封面单张争取压缩到约 150–250KB，保持文字与线条清晰。
