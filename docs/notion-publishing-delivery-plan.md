# 博客与阅读札记：Notion 自动发布实施计划

2026-10-03。状态：待实施。本文基于当前工作区源码核对，仅制定计划，不表示真实同步或部署已经完成。

## 目标与范围

Notion 是唯一写作入口：新建、修改、发布和撤回都在同一个内容库完成。网站分别展示博客和阅读札记，公开内容与助手引用保持一致。首版沿用构建时快照，不新增自建内容数据库或网站编辑后台。

目标链路：Notion 变更 → 验证通知 → 持久记录待同步任务 → 全量读取与校验 → 生成快照和图片资源 → 构建 → 部署 → 核对线上版本 → 记录结果。

自动更新是异步发布。正常情况下以变更后约 5–10 分钟可见为初始验收目标，实际时延以部署平台和真实演练为准；不得承诺即时更新。

## 已有基础与缺口

| 范围 | 当前源码行为 | 下一步 |
| --- | --- | --- |
| 同步 | `scripts/sync-notion.mjs` 全量查询、分页、筛选已发布、校验 slug、原子替换快照 | 保留树结构，补重试、报告和媒体处理 |
| 正文 | `lib/notes.ts` 使用 heading + paragraphs；代码、列表、引用基本文本化 | 引入结构化 block 和富文本 |
| 页面 | `/notes` 为博客，`/bookshelf` 为札记，共用 `NoteArticle` | 共用正文渲染，札记增加明确的摘抄和感想语义 |
| 路由 | 两类详情通过 `generateStaticParams` 构建，`dynamicParams=false` | 保留静态生成；新增文章必须先同步再构建，无需仅为此改成动态路由 |
| 内容来源 | `notion-snapshot.json` 仍为 `enabled:false` | 迁移现有文章后切换，避免首次同步意外替换已有内容 |
| 助手 | 按 `AllowAssistant` 生成章节片段 | 适配新 block，核对撤回和缓存版本失效 |
| 自动化 | 存在 `content:sync`、`content:build`，未见 webhook 或发布工作流 | 补事件入口、可靠任务执行、部署及结果确认 |
| 索引 | 已有 RSS、标签和目录 | 联动 sitemap、canonical、分享信息、搜索和相关项目入口 |

部署平台、生产环境变量、Notion 数据库授权是否已配置，尚未通过线上环境核实。

## 阶段一：内容约定与真实接入

1. 沿用当前 API 字段：Title、Slug、Kind、Status、Summary、Tags、Published、AllowAssistant、Project，以及 SourceTitle、SourceAuthor、SourceURL、SourceLocation。允许 Notion 展示中文说明，但字段名变更需显式映射。
2. Kind 只取博客/阅读札记；Status 使用草稿/已发布/归档。AllowAssistant 独立于发布状态。
3. Slug 首次发布后固定；改标题不改变网址。首版不开放随意改 slug 或类型，必要迁移须提供旧链接处理。
4. 准备博客、札记两个模板。札记用明确命名的“原文摘抄”“我的感想”区域；摘抄使用 quote block，保留来源标题及可用的作者、链接、页码。校验摘抄区域必须提供来源标题，不能根据任意引用块猜测来源。
5. 将当前需要保留的种子文章迁入 Notion，保持 slug；准备一篇真实札记及一篇不应公开的草稿。
6. 配置专用只读集成及数据源 ID，先 dry-run 输出条目清单、变更和错误，再生成快照。令牌只通过本地环境或部署平台 secret 配置。

验收：真实 API 能读到两类内容；草稿、归档不进入快照；已发布且 AllowAssistant=false 的文章正常展示但不进入助手；首次切换无文章意外消失。完整查询得到空库时允许空快照，权限错误和请求失败不能伪装成空库。

## 阶段二：结构化正文与图片

1. 在 `lib/notes.ts` 引入有版本的内容模型，以 Notion page ID/block ID 保持文章与章节身份；读取时保留嵌套 children，替换当前展开子块的逻辑。
2. 支持标题层级、段落、加粗/斜体/删除线/行内代码、链接、有序/无序嵌套列表、代码块及语言、引用、分隔线、图片及图注、基础表格、callout。
3. 改造 `components/NoteArticle.tsx`，必要时拆出 block 渲染器；目录、锚点、阅读时长、RSS 摘要和助手纯文本从同一结构派生。
4. 明确支持范围；不支持的嵌入、复杂数据库等记录 page/block ID 和类型并阻止本次发布，不静默丢失正文。
5. Notion 托管图片在构建时下载到生成的静态资源，以内容哈希命名并随部署发布，避免直接固化临时 URL。图片下载限制协议、大小、类型、超时与重定向，拒绝本地及私网地址；失败时停止部署。首版不依赖额外对象存储。
6. 阅读札记在视觉和语义上区分摘抄、个人感想和出处；图片可缩放，宽表格/代码在移动端局部滚动。

验收：用一篇覆盖所有支持块的样例核对 Notion 与网站；中文、嵌套列表、链接和代码换行正确；部署后的图片不依赖 Notion 临时地址；旧文章仍能读取，章节引用可用。

## 阶段三：自动触发与可靠部署

架构选择：沿用当前托管平台的构建部署能力；增加受签名保护的 webhook 和持久任务状态。优先评估现有 Redis 是否适合保存发布状态，但不能假定助手的可选 Redis 已配置，也不能用进程内内存承担可靠队列。平台核实后选定一个支持重试的任务执行服务和调度入口，再实施工作流。

1. 新增拟定入口 `app/api/notion-webhook/route.ts`：完成订阅验证，对原始请求体进行 HMAC 验签，限定目标集成/工作区和内容库关联范围，按事件 ID 去重。不能仅信任来访 JSON；首次验证令牌不公开返回。
2. 事件只作为“需要重新读取”的信号。持久记录 pending/dirty 状态成功后才确认接收；不要在 HTTP 响应结束后依赖无保障的后台任务。
3. 使用约 60–120 秒合并窗口，串行执行发布；运行期间收到事件，完成后再次读取。根据当前全量数据构建，避免乱序事件恢复旧文章。
4. 全量分页读取、处理媒体、校验结构，再比较规范化内容哈希。临时图片 URL 和抓取时间不参与语义版本；无变化不部署。429 尊重 Retry-After，网络及 5xx 有界退避，字段错误直接报告。
5. 必须部署此次任务生成的同一份快照和资源，不能在独立构建中读到旧仓库快照。生产构建不得在同步失败后继续发布种子或旧快照。
6. 构建及检查成功后才切换生产版本；串行或版本门禁阻止旧构建覆盖新构建。失败保留当前线上版本并记录失败阶段。
7. 增加每小时全量核对作为漏通知补偿，并保留手动重试入口。任务中途退出后能通过租约超时或执行服务重试恢复。
8. 归档、删除、移出内容库、改为草稿均通过完整对账移除；新增 slug 随重建生成。首次接入还须核对实际可订阅事件，不能假定每种变更都会立即发通知。

验收：只在 Notion 操作即可完成新增、修改和撤回；重复/乱序事件不引起旧内容回滚；运行中再次编辑最终可见；重试和漏通知补偿有效。撤回在成功部署前仍可能公开，失败必须明确显示，不能把“Notion 已撤回”写成“网站已下架”。

## 阶段四：发布结果、联动与上线演练

1. 状态记录区分：待同步、同步中、校验失败、构建中、部署失败、线上核验失败、已上线。保存 run ID、内容版本、文章数量、触发时间、完成时间、部署链接及简洁错误。
2. 首版在受保护的任务/部署日志查看结果，附每篇文章 URL 和变更清单；不为状态查询新增公开管理后台。成功回调仍需核对生产域名实际返回的版本。
3. 对新增和修改核对正文及版本；对撤回核对详情 404、列表、RSS、sitemap、站内搜索/命令面板和助手检索均已移除。取消 AllowAssistant 仅影响助手，新请求不能命中旧内容缓存；已发送给访客的历史回答无法追溯收回。
4. 补 `app/sitemap.ts`、`app/robots.ts`，统一生产域名、canonical、文章分享元信息；检查博客和札记标签过滤及项目关联。
5. 手机窄屏与桌面各验一次正文、目录、图片、表格、代码、助手遮挡及减少动效设置。
6. 提供故障处理说明：重试、检查字段、恢复上一成功部署。回滚可能重新公开已撤回内容，执行前必须核对该版本包含的文章。

## 最终验收清单

| 操作或故障 | 预期 |
| --- | --- |
| 博客/札记从草稿改已发布 | 对应列表、详情及索引出现，来源和排版正确 |
| 修改正文、标题或图片 | 同一 URL 更新；线上版本和任务记录一致 |
| 取消 AllowAssistant | 文章仍公开，新助手检索及缓存不再引用 |
| 改草稿/归档/删除/移出库 | 成功部署后各入口移除，原详情返回 404 |
| 完整读取后没有已发布文章 | 正确上线空列表，不恢复种子文章 |
| slug 重复、日期/来源错误、不支持的块 | 不部署，定位到具体页面与错误 |
| API 限流、图片失败、构建或部署失败 | 有界重试或明确失败，当前线上版本保留 |
| 重复通知、并发编辑、任务崩溃、通知丢失 | 去重、后续对账及恢复生效，最终状态与 Notion 一致 |

## 实施顺序和交付物

- 第一批：字段及模板约定、迁移清单、真实同步 dry-run、结构化正文与图片；交付本地可核对的博客和札记。
- 第二批：webhook、持久任务、部署串行控制、定时补偿与状态报告；交付不依赖手动命令的发布链路。
- 第三批：撤回/缓存/索引验证、移动端检查及操作说明；交付真实线上验收记录。

依赖项：Notion 内容库与专用集成权限、当前部署项目及生产域名、可靠任务与定时执行能力、发布所需凭据。开始实现可先使用固定样例和本地测试；接入真实服务前核实上述配置，不在聊天中索要明文密钥。

本轮不扩展缩略图、独立 CMS、向量数据库或全套 Notion 排版复刻；草稿预览先使用 Notion，网站仅发布已发布内容。后续若需要网站私密预览，再单独设计认证与缓存隔离。

验证分层：转换器与同步异常做针对性单元测试；发布状态与重试做集成测试；真实新增/修改/撤回各做一次生产演练。计划文档完成不等于这些验证已执行。写 Next.js 代码前读取安装版本的 `node_modules/next/dist/docs/` 对应指南。
